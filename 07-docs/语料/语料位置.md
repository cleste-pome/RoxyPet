## md → JSON 的转换规则（`03-scripts/import-speech.py`）

md 是求全的原稿（台词＋提示词＋菜单措辞＋说明都在里面）；JSON 只装程序要说的台词。规则如下：

| 规则 | 说明 |
|---|---|
| 1. 只认标题里的分类键 | 只处理 `## 一、闲聊池（chat）` 这种「标题末尾带 `（key）`」的段落；key 不在白名单（chat / morning / day / evening / night / weekend / workday / hover / drag / look_end / lonely / greeting / battery20 / battery10 / battery_full / done / notice / idle / ai_thinking / ai_fail / 八个方位）里的段落整段跳过 |
| 2. 只收代码块里的行 | 段落内 ```text 代码块中的每个非空行＝一条台词；标题、空行、普通正文不收 |
| 3. 原样搬运 | 台词一个字都不改写，`{称呼}`、`{h}` 原样带过去 |
| 4. 别名归一 | 标题写 `greetings`／`thinking`／`fail` 也认，分别归到 `greeting`／`ai_thinking`／`ai_fail` |
| 5. 整点报时表 | 「整点报时（hourly）」下那张两列表，第二列含 `{h}` 的行 → 生成 `hourly_morning` / `hourly_noon` / `hourly_day` / `hourly_evening` / `hourly_default`；不含 `{h}` 的行（如静音时段、洛琪希「中午十二点啦」）不收 |
| 6. 不进 JSON 的东西 | 透视魔法的系统提示词、右键菜单措辞、扩展说明、表头注释、人物卡——程序不读，只给人看 |
| 7. 缺件即报错 | 必需分类（chat / greeting / hover / drag / up / right / down / left / ai_thinking / ai_fail）少一个，脚本直接报错拒跑，不会悄悄生成残缺 JSON |

一句话：**JSON ＝ md 里的全部台词 ＋ 整点表转出的几个键；md 里的非台词内容不进 JSON。**

## 稿源与镜像

- **仓库的 `07-docs/语料/` 是唯一稿源**：要改语料就改这里的 md，再跑 `03-scripts/import-speech.py`（默认就读这个目录）重建 `02-assets/speech/*.json`。
- 项目文件夹里（仓库外）的同名 md 只是镜像：需要时从仓库往外同步，**不要反向覆盖仓库**。
- 仓库要能独立跑起来：`03-scripts/build.sh` 只用本仓库的 `01-src/` 与 `02-assets/`，不依赖仓库外的任何文件。
